# Pyramid-head stack-mask transfer test (locked protocol)

Status: preregistered before the first training run.

## Question

The stack-mask graduation (`STACK_MASK_GRADUATION_PREREG.md`) established, on
the TCN-192 concat head, that the `pre012 = [1, 1, 1, 0, 0, 0]` view is
mean-positive vs `all6` on every paired seed and REAL vs `only1`, with the
largest gains on OSD and class-2.  Its `all6` arms reproduced the immutable
Phase-8 TCN root `p8a_average_s*` to six decimal places, so that finding
already stands relative to the root.

The Phase-8 chain, however, builds every arm from `a0` upward on the
`gated_pyramid_ordinal` head, whose fusion (per-stack biased lateral
projections + softmax gate average) differs from the TCN concat projection.
This test asks the one remaining causal question **before the chain root is
sealed**:

> With the pyramid-minimal head (the chain's `a0` configuration) and the
> complete graph, parameterization, initialization, optimizer, data order,
> and endpoint held fixed, does the `pre012` stack view transfer — i.e. is it
> non-inferior or better than `all6` on the pyramid family too?

This is a representation-view ablation.  It does **not** reduce backbone
compute or latency, and it does **not** run or modify the Phase-8 chain.

## Arms

Configs are generated by `phase8_chain_driver.base_config()` +
`finalize_training_block()` — byte-identical to the chain's `a0` arm except
for the artifact identity fields (`training.log_dir`, seed) and, in the
treatment arm only, `model.head.stack_input_mask`:

| arm | mask for stacks 0..5 | interpretation |
|---|---|---|
| `all6` | absent (= `[1, 1, 1, 1, 1, 1]`) | pyramid-minimal incumbent, the chain's `a0` |
| `pre012` | `[1, 1, 1, 0, 0, 0]` | pre-bottleneck stacks 0–2 |

The mask zeroes the *projected* per-stack feature after norm + lateral
projection and before gated fusion (each pyramid stack owns a biased
projection; masking earlier would leak `silu(bias)` as a constant channel).
It must not remove modules, parameters, or persistent state.  A mandatory
preflight rebuilds both arms from the same RNG state per seed and requires
identical state-dict schema and tensor-value SHA, identical parameter counts
and trainability, complete v3 backbone load (missing/unexpected backbone
keys = 0), and verified mask semantics (perturbing and poisoning masked
slices with non-finite values must not change any output field; perturbing a
kept slice must).

## Locked training and evaluation protocol

Identical to the chain's arm protocol (and to the graduation):

- Seeds: `1234`, `2345`, `3456`; head-only, backbone frozen; init
  `logs/r8_v3_diverse/best_macro_f1.pt`; `require_backbone_complete`;
  `reset_rng_after_init`.
- Head: `gated_pyramid_ordinal`, `d_model=192`, `gate_mode=global`,
  `ordinal_mode=softmax`, `edge_hidden_dim=96`, `use_stage2=false`,
  alignment `average`, no final residual.
- Objective: full legacy v4 loss block; KD, boundary T-MSE, event and
  raw-anchor terms off.
- Training: 3,000 steps, batch 24, AdamW `1e-3`, 500-step warmup, cosine,
  AMP init scale 4096, `max_amp_overflows=0` (any overflow invalidates).
- Endpoint: **locked step 3000**; no best-checkpoint selection.
- Manifests: train `train_manifest_v3.json`, val `val_manifest.json`,
  evaluation `vox_sel.json` (as in the graduation).

Run order balances wall-clock position across arms:

1. seed 1234: `all6`, `pre012`;
2. seed 2345: `pre012`, `all6`;
3. seed 3456: `all6`, `pre012`.

All configs, init, manifests, evaluator, model/data/loss sources, dynamic
Zipformer recipe sources, the chain driver (config generator), this
preregistration, and the runner are SHA-bound.  Completion sidecars bind
inputs and outputs; inputs are re-hashed after evaluation; drift leaves a run
uncertified.  Artifacts are reused only on an exact two-sided lineage match,
otherwise moved to timestamped `.stale.*` paths.

## Statistics and decisions

Primary endpoint: pooled macro-F1, `pre012` vs `all6`, paired by seed.
Bootstrap: seeds averaged within recording, 20,000 resamples of the 116
recordings, RNG seed 0.  Recording sets must match exactly.  Rules are
verbatim from the graduation: operational mean-only NI (mean ≥ −0.002),
strict NI (all seed deltas ≥ −0.002 and bootstrap lower bound > −0.002),
REAL / NEGATIVE / SUGGESTIVE / NONE evidence labels, practical adoption
R2 (mean ≥ +0.005) or R3 (class-2 or OSD delta ≥ +0.010 with mean ≥ −0.002).

Decision — a recommendation for the *chain base config*, applied only with
explicit approval while the chain is held, never by this runner:

1. `pre012` passes operational NI **and** R2 or R3 → recommend adding
   `stack_input_mask: [1, 1, 1, 0, 0, 0]` to `base_config()` (all arms
   `a0`→`e`) before sealing the root.
2. `pre012` is strict-NI but passes neither R2 nor R3 → keep `all6`;
   non-inferiority alone does not justify changing the base.
3. Otherwise → the mask does not transfer to the pyramid family; keep
   `all6` and record the discordance with the TCN result.

Secondary, **descriptive only** (no adoption rule): the paired contrast of
pyramid `all6` against the immutable TCN root `p8a_average_s*` (same seeds,
same recordings), reported so the pyramid base's own level is visible before
the chain runs.  The chain's final +0.010 complexity gate remains referenced
to the immutable TCN root regardless of this test's outcome.

Class-wise and OSD metrics are secondary.  No AMI, teacher, probe, or
intermediate-checkpoint result may alter the locked endpoint or the rules
above.
